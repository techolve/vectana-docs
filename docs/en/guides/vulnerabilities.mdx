Vectana looks up vulnerabilities affecting your registered versions in [OSV](https://osv.dev/) (Open Source Vulnerabilities), which aggregates GitHub Security Advisories, the PyPI advisory database and other major sources.

## Reading the list

![Vulnerability list](/screenshots/en/vulnerabilities.png)

"Vulnerabilities" in the sidebar lists findings across every project you can see. A project's "Vulnerabilities" tab shows only that project.

| Column | Meaning |
| --- | --- |
| Severity | CRITICAL / HIGH / MEDIUM / LOW / UNKNOWN, plus the CVSS score when known |
| Project | The affected project |
| Package | Ecosystem, package name and version, with the package's [recommended upgrade](#recommended-upgrade) below |
| Fixed in | The smallest fixed version newer than yours. Upgrading to it resolves this vulnerability |
| Vulnerability | The advisory ID (GHSA, PYSEC…), aliases such as the CVE, and a summary. Click the ID to open it on osv.dev |
| Detected | When Vectana first found it |
| Status | How you're handling it |

The list is sorted by severity. Filter by keyword, severity and status at the top right.

### About severity

Vectana prefers the rating in the advisory itself (GitHub's Critical / High / Moderate / Low, for example). Without one, it uses the CVSS score: 9.0 or higher is CRITICAL, 7.0 or higher HIGH, 4.0 or higher MEDIUM, and anything lower LOW. With neither, the severity is UNKNOWN.

## Track the status

Change each finding's status to record what you've done.

| Status | Use it when |
| --- | --- |
| Open | It was just found. Counted on the dashboard |
| Acknowledged | You've looked at it — still investigating, or waiting for an update |
| Ignored | It doesn't affect you (you don't use the affected feature, for example) |

Acknowledged and ignored findings aren't counted as open on the dashboard and aren't notified. Members and above can change the status.

## Recommended upgrade

When a package has several vulnerabilities, Vectana shows the version that fixes them all at once as the recommended upgrade. It appears under the package name in the vulnerability list, and in the "Upgrade to" column of the project's Packages tab.

- Open and acknowledged vulnerabilities count. Ignored ones do not
- The recommendation is the newest of their fixed versions, which is the lowest version that fixes all of them
- A patch / minor / major label shows how big the jump is. Major upgrades often include breaking changes, so check the release notes. Below 1.0 (0.x), a minor bump often breaks compatibility too, so it is labeled major
- When some vulnerabilities have no fix yet, "+N without a fix" is added. When none of them has a fix, it shows "No fix yet"

The recommendation is a guide computed from the advisories' fixed versions. After upgrading, import the lockfile again and check that the vulnerabilities are gone.

## Resolve it

Upgrade the package to the fixed version or later, then [import the new lockfile](/guides/packages). When the old version is no longer registered, its findings go away.
