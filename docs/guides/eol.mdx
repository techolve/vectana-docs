サポートが終了したフレームワークや言語は、脆弱性が見つかっても修正されません。Vectana は [endoflife.date](https://endoflife.date/) のデータを使って、サポート期限を確認します。

## 状態の意味

| 状態 | 意味 |
| --- | --- |
| サポート終了 | サポート期限を過ぎています。新しい系統への移行が必要です |
| まもなく終了 | 期限まで残りわずかです（何日前から表示するかは [管理者が設定](/admin/settings)。初期値は 90 日） |
| サポート中 | 期限まで余裕があるか、期限が決まっていません |
| 不明 | 製品は分かりましたが、バージョンに合うリリース系統が見つかりませんでした |

一覧では、サポート終了 → まもなく終了 の順に、期限が近いものから並びます。EOL 日の下に「あと ◯ 日」「◯ 日前に終了」と表示されます。

## パッケージは自動で判定されます

[登録したパッケージ](/guides/packages) のうち、endoflife.date に登録されている製品（Next.js・React・Django・Laravel・Spring Boot など）は自動で判定されます。何もする必要はありません。

バージョンは、そのリリース系統に当てはめて判定します。たとえば Next.js 16.4.3 は「16」系、Python 3.10.4 は「3.10」系として扱います。

## ランタイムを登録する

言語・データベース・OS など、lockfile には出てこないものは**ランタイム**として登録します。プロジェクトの「EOL」タブで登録します。

<Steps>
  <Step title="製品を検索する">
    「製品を検索」に `python`・`node`・`postgres`・`ubuntu` などと入力し、表示された候補から選びます。
  </Step>
  <Step title="バージョンを入力する">
    使っているバージョン（`3.14`、`24.18.0`、`24.04` など）を入力して「追加」を押します。
  </Step>
</Steps>

登録するとすぐに判定されます。結果が出るまで数秒かかることがあります。「EOL を再判定」を押すと、すぐに判定し直します。

## mise.toml・.tool-versions から取り込む

[mise](https://mise.jdx.dev/) の `mise.toml`（`.mise.toml`・`mise.local.toml` も可）や、asdf の `.tool-versions` を「パッケージ」タブにドロップすると、`[tools]` に書かれたツールがランタイムとして登録されます。

```toml mise.toml
[tools]
python = "3.14"
node = ["24", "22"]
postgres = { version = "18" }
java = "temurin-21"
uv = "latest"
```

- `node` → Node.js、`postgres` → PostgreSQL のように、endoflife.date の製品名と別名で自動的に対応付けます
- Java は `temurin-21`・`corretto-17` のようにベンダー付きで書かれたものを、そのベンダーの製品として登録します
- 複数バージョンや `{ version = "…" }` の書き方、`prefix:18` にも対応しています

次のものは取り込まれず、取り込み後に理由が表示されます。

| 理由 | 例 |
| --- | --- |
| EOL 情報なし | endoflife.date にデータがないツール（`uv`、`git-cliff` など） |
| バージョン未固定 | `latest`・`lts`・`system` など、どのバージョンか決まらないもの |

ランタイムのバッジには、取り込んだファイル名が表示されます。同じファイル名で取り込み直すと差分が反映され、手で登録したランタイムはそのまま残ります。
