登録したパッケージのバージョンに影響する脆弱性は、[OSV](https://osv.dev/)（Open Source Vulnerabilities）のデータベースで調べています。GitHub Security Advisories や PyPI のアドバイザリなど、主要なデータを横断して確認できます。

## 一覧の見方

![脆弱性の一覧](/screenshots/ja/vulnerabilities.png)

サイドバーの「脆弱性」で、見えているプロジェクト全体の脆弱性を確認できます。プロジェクトの「脆弱性」タブでは、そのプロジェクトの分だけが表示されます。

| 列 | 内容 |
| --- | --- |
| 重大度 | CRITICAL / HIGH / MEDIUM / LOW / UNKNOWN と、分かる場合は CVSS スコア |
| プロジェクト | 影響を受けるプロジェクト |
| パッケージ | エコシステムとパッケージ名・バージョン。その下に、パッケージの[推奨バージョン](#推奨バージョン)が出ます |
| 修正版 | 今のバージョンより新しい修正版のうち、もっとも小さいバージョン。ここまで上げればこの脆弱性は解消します |
| 脆弱性 | 脆弱性の ID（GHSA・PYSEC など）と CVE などの別名、概要。ID を押すと osv.dev の詳細が開きます |
| 検知日時 | Vectana が最初に見つけた日時 |
| 担当者 | 対応する人。決まっていなければ「未割り当て」 |
| 期限 | 対応の期限。過ぎていて未完了のものは赤字で「期限切れ」と出ます |
| 状態 | 対応状況 |

右端のボタンを押すと[詳細パネル](#詳細パネル)が開きます。コメントがある行は、ボタンにコメントの件数が出ます。

一覧は重大度の高い順に並びます。右上では次の条件で絞り込めます。

- キーワード（プロジェクト名、パッケージ名、脆弱性 ID、概要、担当者名）
- 重大度
- 状態（未対応・未完了（未対応＋確認済み）・確認済み・無視・すべて）
- 担当者（すべて・自分の担当・未割り当て）
- 期限（すべて・期限切れ）

### 重大度について

重大度はアドバイザリに記載された評価（GitHub の Critical / High / Moderate / Low など）を優先し、ない場合は CVSS スコアから判定します（9.0 以上: CRITICAL、7.0 以上: HIGH、4.0 以上: MEDIUM、それ未満: LOW）。どちらもない場合は UNKNOWN になります。

## 対応状況を管理する

各行の「状態」を切り替えて、対応状況を記録します。

| 状態 | 使いどころ |
| --- | --- |
| 未対応 | 見つかったばかり。ダッシュボードの件数に含まれます |
| 確認済み | 内容を確認した。影響の調査中や、アップデート待ちなど |
| 無視 | 影響がない（その機能を使っていない、など）と判断した |

「確認済み」と「無視」にしたものは、ダッシュボードの未対応の件数に含まれず、通知もされません。状態を変えられるのは、プロジェクトのメンバー以上のロールを持つ人です。

「未対応」と「確認済み」は、まだ片付いていない**未完了**として扱います。担当者の件数や期限切れの判定は、未完了のものが対象です。

## 詳細パネル

一覧の右端のボタンを押すと、画面の右側に詳細パネルが開きます。ここで次のことができます。

- **状態・担当者・期限の変更**: 変更はすぐに保存されます
- **コメント**: 対応方針や調査結果を書き残せます。Ctrl+Enter（Mac は ⌘+Enter）でも投稿できます
- **変更履歴**: 誰がいつ、状態・担当者・期限を何から何に変えたかが、コメントと一緒に時系列で並びます

### 担当者と期限

- 担当者に選べるのは、そのプロジェクトのオーナーとメンバーです。閲覧のみのメンバーは選べません。会社管理者などの、メンバーでなくても対応できる人は、自分自身を担当者にできます
- 期限は日付で指定します。期限を過ぎても未完了のものは「期限切れ」として表示され、ダッシュボードの件数にも出ます
- 担当者や期限を空に戻すこともできます。その操作も履歴に残ります

### コメントと履歴の権限

- コメントを書けるのは、プロジェクトのメンバー以上のロールを持つ人です。閲覧のみのメンバーは、読むことだけができます
- コメントを削除できるのは、書いた本人と、プロジェクトを管理できる人（オーナーや会社管理者など）です
- 変更履歴は削除できません

パッケージを上げて脆弱性が[解消](#解消する)されると、その脆弱性はコメントや履歴ごと一覧から消えます。残しておきたい内容は、チケットなどにも記録してください。

## 推奨バージョン

1つのパッケージに脆弱性が複数あるとき、どこまで上げればまとめて直るかを「推奨バージョン」として表示します。脆弱性の一覧ではパッケージ名の下に、プロジェクトの「パッケージ」タブでは「推奨バージョン」の列に出ます。

- 未対応と確認済みの脆弱性が対象です。無視したものは含めません
- それぞれの脆弱性の修正版のうち、いちばん新しいものを推奨します。これがすべてを直す最小のバージョンです
- 今のバージョンからの上がり幅を patch / minor / major で示します。major は互換性のない変更を含むことが多いので、リリースノートを確認してください。1.0 未満（0.x）のパッケージは minor の上げでも互換性が壊れることが多いため、major として扱います
- 修正版がまだ出ていない脆弱性があると「ほか修正版なし N 件」と添えます。どれにも修正版がない場合は「修正版なし」と表示します

推奨バージョンはアドバイザリの修正版から計算した目安です。上げたあとは lockfile を取り込み直して、脆弱性が消えたことを確認してください。

## 解消する

脆弱性を解消するには、パッケージを修正版（まとめて直すなら推奨バージョン）以上に上げてから、新しい lockfile を [取り込み直します](/guides/packages)。古いバージョンが登録から消えると、その検知結果も消えます。
