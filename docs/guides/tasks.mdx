作業はすべて「タスク」で管理します。同じタスクが、ダッシュボードの「タスク」、ガント、ボード、保守の一覧に出ます。

## タスクの種類 [#kinds]

| 種別 | 使い方 |
| --- | --- |
| 開発 | 機能の開発・不具合の修正など |
| セキュリティ対応 | パッケージやランタイムのアップグレード。脆弱性と EOL の対応をまとめます（[下記](#security)） |
| その他 | レポート作成・環境の準備など |

タスクには担当・開始日・期限・状態（未着手・対応中・完了）・見積時間・説明を入れます。担当にできるのは、そのプロジェクトのメンバーのうちビューアー以外の人です。プロジェクトのメンバー（ビューアー以外）と管理できる人がタスクを作成・編集でき、ビューアーは見るだけです。

## 表示の切り替え [#views]

プロジェクトの「タスク」タブは、プロジェクトの進め方と段階に合わせた表示で開きます。上のボタンで「ガント」「ボード」「一覧」を切り替えられます。

| プロジェクト | 最初に開く表示 |
| --- | --- |
| 進め方が「ウォーターフォール」 | ガント |
| 進め方が「スクラム」 | ボード |
| 段階が「運用・保守」 | 一覧（進め方に関係なく） |

進め方は「概要」タブの「編集」で変更します。

### ガント [#gantt]

左にタスク、右に期間のバーが並びます。

- **フェーズ**：タスクの「親タスク」を選ぶと、その下にまとまります。親のバーは子タスク全体の期間を表します
- **マイルストーン**：「マイルストーン」にチェックすると、開始日の 1 日だけのひし形になります
- **依存関係**：「先に終わらせるタスク」を選ぶと矢印でつながります。先のタスクが終わる前に始まる予定だと、矢印が赤くなります
- バーの濃い部分が進み具合（%）です。期限を過ぎて完了していないバーは赤く表示されます
- 赤い縦線が今日です。「日」「週」で目盛りの細かさを変えます

開始日も期限もないタスクは、左の一覧にだけ出ます。バーやタスク名を押すと編集できます。

### ボード（スクラム） [#scrum]

スプリントごとに「未着手」「対応中」「完了」の列にカードが並び、左に「バックログ」（どのスプリントにも入っていないタスク）が出ます。

1. 「スプリントを作成」で、名前・期間・スプリントゴール・完成の定義を入れます
2. バックログのカードの「スプリントへ」で、タスクを今のスプリントに入れます。カードにはポイントを入れておきます
3. 「開始する」でスプリントを進行中にします。進行中にできるのは 1 プロジェクトに 1 つです
4. カードを列へドラッグして状態を変えます
5. 期間が終わったら「スプリントを完了」を押します。未完了のタスクはバックログに戻ります

完成の定義の項目はボードの上でチェックできます。

- **バーンダウン**：スプリントの残りポイントを日ごとに表示します。点線が理想の線です。ポイントが 1 つも入っていないスプリントは、タスクの件数で数えます
- **ベロシティ**：開始したスプリントごとの計画ポイント（灰色）と完了ポイント（黒）です。直近 4 回の完了したスプリントの平均も出します。計画ポイントは、スプリントを完了したときの値で残ります

### 一覧（保守） [#list]

期限順に「期限切れ」「今週」「来週以降」「期限なし」でまとめて表示します。「担当者別」に切り替えると担当ごとにまとまります。担当と種別で絞り込め、「完了も表示」で完了したタスクも出せます。

## セキュリティ対応タスク [#security]

1 つのセキュリティ対応タスクは、**パッケージ（またはランタイム）のアップグレード 1 回**です。たとえば axios に脆弱性が 2 件あれば、1 つのタスクに 2 件が紐づきます。同じパッケージの EOL も同じタスクに入ります。

プロジェクトの「セキュリティ対応」タブに、タスクとまだタスクになっていないものが並びます。

### 自動で作られるもの [#auto]

スキャンのたびに、次のものはタスクが自動で作られます。

- 重大度が **しきい値以上** の未対応の脆弱性（重大度が不明なものも含む）
- **サポートが終了した（EOL）** パッケージ・ランタイム

しきい値は「セキュリティ対応」タブの上で変えられます（初期値は HIGH 以上）。変えられるのはプロジェクトを管理できる人です。

同じパッケージのタスクがすでにあれば、新しく見つかった脆弱性はそのタスクに追加されます。しきい値未満の脆弱性も、同じパッケージの未完了のタスクがあればそこに入ります。

### タスク化 [#manual]

しきい値未満の脆弱性と、EOL が近いものは「しきい値未満でまだタスクになっていないもの」に並びます。「タスク化」を押すとタスクになります。チェックを入れて「選んだものをまとめてタスク化」もできます。

### 推奨バージョンと期限 [#due]

タスクには、今のバージョンと推奨バージョン（紐づく脆弱性をすべて直せる最も低いバージョン、[推奨バージョン](/guides/vulnerabilities)）が出ます。

タスクの期限を入れなければ、紐づく脆弱性のうち最も早い期限（脆弱性ごとの期限、なければ重大度ごとの SLA）がタスクの期限になります。EOL だけのタスクは、サポート終了日が期限です。こうして決まった期限には「*」が付きます。

### 自動で完了するもの [#done]

紐づく脆弱性と EOL がすべて片付くと、タスクは自動で完了になります。

- パッケージを上げて lockfile を [取り込み直す](/guides/packages) と、古いバージョンの脆弱性が消えて完了します
- 脆弱性を「無視」にした場合も、残りがなければ完了します
- 手で「完了にする」を押すこともできます

タスクを削除すると、紐づいていた脆弱性と EOL は「まだタスクになっていないもの」に戻ります。脆弱性ごとの担当者・期限・コメント（[脆弱性](/guides/vulnerabilities)）はタスクとは別に残ります。

## ダッシュボードのタスク [#dashboard]

ダッシュボードのいちばん上に、未完了のタスクが期限切れ・期限の近い順に出ます。

| タブ | 出るもの |
| --- | --- |
| 自分 | 自分が担当のタスク |
| チーム | 自分がメンバーのプロジェクトのタスク |
| 未割り当て | 自分がメンバーのプロジェクトで、担当がいないタスク |

行を押すとそのプロジェクトを開きます。
