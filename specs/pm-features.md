# PJ管理機能 仕様

- 状態: 合意済み（実装前）
- 決定日: 2026-11-07
- 対象: techolve/vectana

Vectana を、脆弱性・EOL 管理に加えて、営業（引き合い〜受注）から開発・保守までを1つの PJ で追えるアプリにするための仕様です。ヒアリングで決めた内容をまとめています。画面のデザインは別途作成したモックアップ（ダッシュボード、脆弱性一覧、組織ビュー、ガント、スクラムボード、RFP からの見積シミュレーション）に従います。

> このファイルはドキュメントサイトには公開されません（`docs/` の外に置いています）。機能をリリースしたら、利用者向けの説明は `docs/` に書きます。

## 1. PJ・案件・顧客

### PJ とステータス

- 営業の「案件」と開発の「PJ」は分けず、**PJ 1つ**で扱う。引き合いの時点で PJ を作る。
- PJ は「ステータス」を持つ。

  | ステータス | 意味 |
  | --- | --- |
  | 引き合い | 問い合わせを受けた |
  | 提案・見積 | 提案書・見積を作成中 |
  | 商談中 | 見積を提出し、回答待ち・交渉中 |
  | 受注 | 受注した（開発の開始前） |
  | 開発中 | 開発中 |
  | 運用・保守 | 納品後の運用・保守 |
  | 保留 | 一時的に止まっている |
  | 失注 | 失注した |

- 営業を通らない社内システムの PJ は、「開発中」や「運用・保守」から始められる。
- 1つの受注で複数のシステムになる場合も PJ は1つでよい。PJ はすでに複数の取り込み元（リポジトリ・SBOM の `source`）を持てる。
- 失注した PJ はアーカイブし、通常の一覧には出さない。失注理由・競合・金額は残し、後から分析できるようにする。

### 見積

- 見積は PJ の下に**複数**持てる。初回開発、追加開発、保守契約の更新は、どれも同じ PJ の中の新しい見積として作る。
- 受注・失注は見積ごとに記録する。

### 顧客

- 「顧客」マスタを新しく作る（会社名、担当者名、連絡先、メモ）。
- 今ある「会社」（親会社・関連会社・BP）とは分ける。「会社」は自分たちのグループ側の組織、「顧客」は取引先。

## 2. タスク

### タスクの種類

- タスクは1種類のモデルにまとめ、ダッシュボードの「自分のタスク」、ガント、ボード、保守一覧のすべてに同じ形で出す。
- 種別は **開発／セキュリティ対応／その他** の3つ。
- 脆弱性対応と EOL 対応は「セキュリティ対応」にまとめる。脆弱性か EOL かは、タスクに紐づく元データから判別し、絞り込みに使う。

### セキュリティ対応タスク

- 単位は「パッケージ（またはランタイム）のアップグレード1回」。たとえば lodash の脆弱性が3件あれば、1つのタスクに3件を紐づける。
- タスクには推奨アップグレード先のバージョンを表示する（既存の `upgrade` の計算を使う）。
- 重大度がしきい値（例：High）以上の脆弱性は、自動でタスクを作る。しきい値未満は、人が「タスク化」ボタンで作る。しきい値は PJ ごとに設定する。
- 脆弱性の担当者・期限・コメント・履歴（既存のトリアージ機能）とタスクの関係は、実装の設計で決める。期限切れの判定は、既存の「自分で決めた期限、なければ SLA」のルールに合わせる。

### 進め方（ガント／スクラム）

- PJ ごとに進め方を選ぶ。
  - **ウォーターフォール**：ガント（フェーズ、開始日・終了日、依存関係）を表示
  - **スクラム**：ボード（スプリント）、バーンダウン、ベロシティを表示
- 中のデータはどちらも同じタスクなので、将来「両方を表示」の設定を足せるようにしておく。
- ステータスが「運用・保守」の PJ は、進め方の設定に関係なく、保守用のシンプルなタスク一覧（期限順・担当者別）を使う。セキュリティ対応タスクは主にここに出る。

## 3. ロールと権限

### 全体ロール

- 1人のユーザーに**複数のロール**をつけられるようにする（今は1人1つなので作り直す）。
- 最初に用意するロール：

  | ロール | できること |
  | --- | --- |
  | グループ管理者 | グループ全体の管理 |
  | 会社管理者 | 自社の管理 |
  | 営業 | 自社の顧客・見積の作成・編集 |
  | 経理 | 請求・原価を見る、請求済み・入金済みをつける |
  | PMO | すべての PJ を横断して見る |

- ロールは後から追加できる作りにする。
- BP（協力会社）に所属するユーザーには、営業ロールをつけられない。
- 営業ロールで見られるのは**自社の**顧客・見積だけ。

### 金額の見え方

| 情報 | 営業・管理者・経理 | プロパーの PJ メンバー | BP のユーザー |
| --- | --- | --- | --- |
| 見積金額・工数・利益率 | 見える | 見える | 見えない |
| 人ごとの単価（原価） | 見える | 見えない | 見えない |
| 顧客・PJ のステータス・受注金額 | 見える | 見える | 見えない |
| タスク・脆弱性（参加 PJ） | 見える | 見える | 見える |

- プロパーに金額を隠さないのは、キャリアを積むうえで知っておいてほしい情報だから。人ごとの単価は給与が推測できてしまうので隠す。
- 営業中（引き合い〜商談中）の PJ が見えるのは、営業ロール、管理者、その PJ のメンバーだけ。

## 4. GitHub/GitLab 連携

- 接続先：github.com、gitlab.com、セルフホストの GitLab。
- 同期するもの：
  - Issue ⇔ タスク
  - マイルストーン ⇔ スプリント
  - ラベル ⇔ 種別・優先度
  - PR がマージされたら、紐づくタスクを自動で完了にする
- 同期は**双方向**。タイトル・状態・担当者・ラベルは、どちらで変えても反映する。見積工数や見積との紐づけなど、Vectana にしかない項目は Vectana だけで持つ。
- 自動で作られたセキュリティ対応タスクは、Issue としても作る。PJ の設定で切り替えられ、**デフォルトはオン**。
- ロックファイル・SBOM の取り込み：
  - デフォルトブランチへの push をきっかけに、対応しているロックファイル・SBOM を自動で探して取り込む
  - 取りこぼし対策として、1日1回の定期取り込みもする
  - 探す場所は PJ の設定で絞り込める
  - 今ある CI 用トークンでの取り込みはそのまま残す

## 5. ライセンスと開発の進め方

- 当面は OSS として公開し、誰でも自分の環境で使えるようにする。将来は SaaS や有償版も考える。
- 営業機能も同じリポジトリに入れ、すべて AGPL-3.0 で公開する。
- 外部からの PR は当面受け付けない。将来の有償版でライセンスを自由に決められるようにするため。
  - 要望・アイデア・質問は GitHub Discussions（「アイデア」「Q&A」カテゴリ）で受ける
  - バグ報告は Issue（テンプレートつき）で受ける
  - CONTRIBUTING.md に方針を書く
  - 外部の PR を受けるようにするときは、CLA への同意を条件にする

## 6. 画面

### PJ 一覧

- タブ：営業中／進行中／保守／終了（失注・保留は普段は見えない場所に置く）。
- 表示は「表」と「パイプライン」を切り替えられる。営業中タブはパイプライン、進行中・保守タブは表を最初に出す。
- パイプライン：
  - ステータスごとの列に PJ のカードが並ぶ
  - カードには顧客名、PJ 名、見込み・見積金額、確度、次のアクションの日付を出す
  - カードを別の列へドラッグすると、ステータスが変わる
  - 列の上に件数と金額の合計を出す
  - 期限を過ぎた「次のアクション」があるカードは赤くする

### 商談メモ（活動記録）

- PJ ごとの時系列の記録。
- 項目：種類（打合せ／電話／メール）、日付、参加者、内容、次のアクション。
- 次のアクションは担当者のタスクになり、「自分のタスク」にも出る。

### 見積と実績

- 日ごとの工数入力画面で、タスクごとに作業時間を記録する。
- 見積の工数と、PJ 単位・フェーズ単位で比べる。
- 将来の構想：コードを書いている時間をタイマーで自動計測する機能、VS Code 拡張。

### 請求

- 第1段階：受注した見積から請求予定を作る（一括・分割・月額保守）。経理ロールが「請求済み」「入金済み」をつける。請求書の発行は会計ソフトで行う。
- 第2段階：freee やマネーフォワードなどの会計ソフトに請求データを送る連携をつける。インボイス制度と電子帳簿保存法への対応は会計ソフトに任せる。
